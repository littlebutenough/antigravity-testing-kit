Test automation becomes flaky if using hardcoded data for unique fields (Email, Username, Customer Code...).

Please design **Test Data Strategy** according to the following requirements:

## 1. Data Generator Class

Write a Utils/Helper class to automatically generate data:
- Use appropriate library: **Faker** (JS/TS), **JavaFaker** (Java), or UUID
- Each function generates one specific type of data

## 2. Traceable Format

Data must follow format:
```
[Prefix]_[TestName]_[Timestamp]_[Random]
```

Specific examples:
```
Email:    auto_createCustomer_20260402_A3F2@test.com
Username: auto_login_20260402_7B4D
Code:     KH-20260402-A3F2
Phone:    09[random 8 digits]
```

> Looking at database or log → immediately know which test generated this data.

## 3. Data for Each Test Type

| Test Type | Data Requirement | Example |
|-----------|-----------------|---------|
| **Happy Path** | Valid data, correct format | `valid_email@test.com`, `Test@12345` |
| **Negative** | Wrong format, missing field | `invalid-email`, `""`, `null` |
| **Boundary** | Data at min/max boundaries | `"A"` (1 char), `"A"*256` (exceeds max) |

## 4. Integration into Project

Guide on how to use this data set in Test Cases:

Playwright:
```typescript
import { DataGenerator } from '../utils/data-generator';
const testData = DataGenerator.createCustomer();
```

Selenium/Java:
```java
import utils.DataGenerator;
String email = DataGenerator.generateEmail("createCustomer");
```

## 5. Mandatory Rules (refer to `.agent/rules/automation_rules.md`)

- ❌ DO NOT hardcode data for unique fields
- ❌ DO NOT use duplicate data between tests
- ✅ Data must be unique each run
- ✅ Data must be traceable (know which test generated it)
- ✅ Support parallel execution without conflict
