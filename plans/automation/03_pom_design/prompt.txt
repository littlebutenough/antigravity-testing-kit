Based on the list of locators **collected from real DOM** in Step 2, design the **Page Object Model (POM)** architecture.

## Requirements:

### 1. Define Page Class

- Each page/section is a separate class
- Class name should have clear semantic meaning
- Example: `LoginPage`, `DashboardPage`, `CustomerFormPage`, `CustomerListPage`

### 2. Declare Locators

- Use exactly the locators collected in Step 2
- Prioritize robust selectors: `data-testid`, `id`, `name`, `role`
- **Do not change** locator compared to Step 2 unless there is a reason

Playwright example:
```typescript
readonly emailInput = this.page.getByLabel('Email');
readonly submitButton = this.page.getByRole('button', { name: 'Submit' });
```

Selenium example:
```java
private final By emailInput = By.id("email");
private final By submitButton = By.cssSelector("button[data-testid='submit-btn']");
```

### 3. Encapsulate Methods

- Name methods based on business actions (not technical actions)
- Each method performs **one clear action**
- Return `this` or next Page (fluent pattern)

```
✅ CORRECT: fillCustomerForm(), submitAndVerifySuccess()
❌ WRONG:  clickButton(), inputText()
```

### 4. Important Rules

- ⛔ **DO NOT generate Test script file** — only design Page classes
- ✅ Outline file structure, class names, locator declarations, method signatures
- ✅ Can write method body if logic is clear
- ✅ Adhere to `.agent/rules/automation_rules.md` (naming conventions, POM structure)
